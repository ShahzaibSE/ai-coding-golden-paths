# Glossary

Short definitions of the terms used across this repository. Each entry links to the document that owns the topic.

Related: [User guide](user-guide.md) · [Architecture](architecture.md)

## Core concepts

**Golden Path**: The paved, recommended way to build something, with standards, conventions, and workflows already decided. → [README](../README.md)

**Core**: Universal, vendor-neutral engineering knowledge that is always included: standards, workflows, governance. Lives in `core/`. → [Architecture](architecture.md#layers)

**Standard**: A core document of rules that hold for any stack (engineering, testing, security, git workflow). → `core/standards/`

**Workflow**: A step-by-step procedure for a recurring task (implementation, code review, retrieval evaluation). Defined by core or added by a profile. → `core/workflows/`

**Governance**: Baseline policy that constrains how the project handles data, currently the privacy baseline. → `core/governance/`

**Profile**: Composable, vendor-neutral guidance for one technology or domain, such as `runtime/python-backend` or `ai/rag`. → [Profile contract](profile-contract.md) · [Creating a profile](creating-a-profile.md)

**Dependency**: A profile's `requires` entry. Selecting the profile automatically adds the profiles it requires. → [Profile contract](profile-contract.md)

**Conflict**: A profile's `conflicts` entry. Selecting both profiles stops generation with an error. Also used for an existing target file the generator would have to overwrite. → [Architecture](architecture.md#composition-and-conflicts)

**Preset**: A named list of profiles with no guidance of its own, such as `fastapi-rag`. → [ADR-0004](decisions/adr-0004-presets-are-composition-only.md)

**Adapter**: Code that renders the shared knowledge into one coding agent's native configuration. Lives in `adapters/<tool>/`. → [Adding an adapter](adding-an-adapter.md)

**Bootstrap**: The generator in `bootstrap/` that validates, composes, and writes a project (`bootstrap/init.py`). → [User guide](user-guide.md)

**Manifest**: Two meanings. (1) A source manifest: `profile.yaml`, `core.yaml`, or a preset file. (2) The target manifest: `.golden-paths.yaml` in a generated project, which records the selection and file hashes. → [ADR-0005](decisions/adr-0005-yaml-for-manifests.md)

**Generated Project**: A project produced by the bootstrap. It owns all of its files and has no runtime dependency on this repository. → [Architecture](architecture.md#the-generated-project)

**Shared knowledge tree**: `docs/engineering/` in a generated project. It is the single copy of the knowledge, and every agent reads it. → [ADR-0006](decisions/adr-0006-single-neutral-knowledge-tree.md)

**Personal Context**: Developer- or machine-specific instructions and settings. They never go into generated or shared files. → [Personal context](personal-context.md)

**Tool-Specific Context**: Files only one coding agent reads (CLAUDE.md and `.claude/`, AGENTS.md). Generated by adapters; contains pointers, not knowledge. → [Architecture](architecture.md#adapters)

## Tool-specific terms

**CLAUDE.md** *(Claude Code)*: The project instruction file loaded in every session. The generated one is a concise contract that imports `PROJECT.md`.

**AGENTS.md** *(Codex, and other agents)*: The project instruction file Codex reads. The generated one is a project map that links into `docs/engineering/`.

**Rule** *(Claude Code)*: A file in `.claude/rules/`. A `paths:` glob makes it load only when matching files are touched. Generated for each profile that has `applies_to`.

**Skill** *(Claude Code)*: A reusable procedure in `.claude/skills/<name>/SKILL.md`, loaded on demand. Generated for each workflow.

**Agent** *(Claude Code)*: A subagent definition in `.claude/agents/` for delegated specialist work. v0.1 generates `code-reviewer`.

**Hook** *(Claude Code)*: A shell command that runs at a fixed lifecycle event, for deterministic enforcement. Not generated in v0.1. → [Architecture](architecture.md#adapters)
